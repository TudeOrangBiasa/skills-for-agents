# Principles

Twenty rules behind the `/whips` triggers. In the reply, name each one that changed a decision and the choice it changed. Four more upstream principles stay embedded in the triggers and skills that already carry them rather than as separate rules: exhaust-the-design-space as design-it-twice and foundational-thinking as `codebase-design` (see `SKILL.md` section 3), laziness as rule 1, reader load as the `codebase-design` vocabulary.

1. **Subtract before you add.** Delete dead code, one-caller wrappers, and redundant checks first. Then build the smallest change that solves the problem on the simpler base. A speculative "might help" change gets reverted.
2. **Fix the root cause.** Reproduce first, then ask why until you reach the cause. A guard that silences the symptom is not a fix.
3. **Prove it works on the real artifact.** Run the app, the endpoint, the migration, or the page the user will hit. "It compiles" and "CI is green" are inputs, not proof.
4. **Small verifiable units.** Each commit and each PR ends in a check that passes on its own. Verify one unit before starting the next, and order them so the sequence proves itself.
5. **Model the domain.** Name the data shape before logic: a state machine, a typed model, a table or registry. Scattered conditionals that repeat one assumption mean the shape is missing.
6. **Make operations idempotent.** Commands, migrations, jobs, and loops reach the same end state when they run twice or crash halfway.
7. **Test behavior, not implementation.** Call the code the way its users do and assert a literal expected result. A test that still passes when the code returns nothing gets rewritten or deleted.
8. **Never block on the human for reversible work.** Proceed, show the result, let the human correct course. Save questions for the pause list in `SKILL.md` section 5 and for product calls no experiment can settle.
9. **Attack the premise.** Two fixes that assumed one sentence and failed the same gate mean the sentence is suspect, not the fixes. Write the premise down, count the imbalance per actor with a rerunnable script (rule 12), and remove the asymmetry instead of compensating for it (rule 1). If the count is even across actors, the premise is innocent; keep the count as evidence and look elsewhere.
10. **Boundary discipline.** Validate, narrow types, and handle errors at system boundaries (CLI args, config, network, external APIs); trust internal types and keep business logic in pure functions. No re-validation deep in call chains, no framework types leaking through the public surface. Ask whether the data is crossing a boundary right now, and whether the logic can be a pure function the shell just calls.
11. **Type system discipline.** Make illegal states unrepresentable: sum types over bags of optional fields, branded primitives over bare strings, exhaustive matches the compiler checks. Parse external data into the typed model at every boundary (rule 10); never cast past the compiler, push the check up into the type instead. A runtime "should never happen" marks the place a type is too weak.
12. **Build the lever.** Non-trivial work gets a tool that does it or proves it (codemod, script, generator, delegate brief), not hand edits. Do the first unit by hand to learn the recipe, then encode it, prove it by rerunning on that unit, and commit it when the work outlives the session. If you cited this rule and no tool is in the diff, you did not apply it.
13. **Encode lessons in structure.** The second time you write the same instruction, stop writing text and build the guardrail: a lint, a metadata flag, a runtime check, a script. If the lesson needs judgment and cannot be encoded, make the instruction prominent with an example of the failure. A structural fix replaces the instruction, never joins it.
14. **Migrate callers, then delete.** A new internal API means inventorying callers, migrating them, and deleting the old one in the same wave. No compatibility layers kept only because internal callers still exist; adapters are exceptional and time-boxed. Update tests to the new contract and delete tests that only guard pre-refactor details. Applies only when no external user needs backward compatibility.
15. **Separate before serializing.** Concurrent actors sharing one mutable file, branch, key, or object get separate owned targets first (each its own file, key, branch, or state directory, merged only at read time). Serialize structurally (lockfiles, sequential phases, single writer) only when one shared target is a real invariant. Instructions are not concurrency control.
16. **Outcome-oriented execution.** Planned rewrites converge on the target architecture; intermediate breakage is acceptable when planned, scoped, and reversible. Declare where breakage is allowed, keep high-signal checks on touched areas, and require full verification at plan completion. No throwaway compatibility code that becomes permanent.
17. **Redesign from first principles.** A new requirement is not bolted on; redesign as if it had been foundational from day one. Read every affected file, ask what you would build from scratch with this requirement, propagate through types, docs, and examples, then deliver incrementally.
18. **Experience first.** When implementation convenience conflicts with user delight, delight wins; ship fewer polished features over more rough ones. Prototype in throwaway form before committing, tighten the core loop, get the details right. The user is whoever consumes the work, including the importing colleague and the next maintainer.
19. **Explain the number.** Before trusting a measured number, name what bounds it (ask why not double) from a profile or counters, never from reading code. List what else it could be measuring (errors, skipped or cached work, noise, a piece too small to matter) and rule each out with evidence. Keep run count, spread, and limiter with the number.
20. **Guard the context window.** Bulk goes to delegates, summaries stay in this thread; raw payloads never ride along. Size phases, cap files per phase, set turn budgets. Parse large artifacts in a subagent and keep only the reduced finding.
