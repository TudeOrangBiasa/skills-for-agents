# Playbook: orchestrate

You own the program, never the code. Author briefs, drain the queue, keep the frontier green, decide. For work handed to one standing coordinator chat that outlives any single agent: multi-day, many stacked PRs, dozens of workers, the human checking in twice a day instead of every five minutes. One task to a predicate is a single unattended run with a checkable exit condition; one ambitious run needing a bespoke workflow is figure-it-out. Route here when the work outlives any single agent. Work one agent could finish inside the session budget is not a program.

Three rules carry the rest: completions are queue events, never interrupts; every spawn and every resume carries the standing orders verbatim (directives decay across resumes, each dropped one costs a human turn); the brief is the product (a vague brief fails quietly, because a worker cannot ask questions).

## Roles

- **Coordinator (this chat).** Frames, authors briefs, drains completions, owns the human report, makes judgment calls. Never authors or edits code; conflicted merges and code changes are always tasked units. Models per role from the repo model map. It may land verified units itself where local git is cheap; queueing finished work behind an idle stacker harvests nothing at deadline.
- **Track leads.** Only past what one coordinator drains alone: one per track (build, landing, verification are common cuts), each owning its units, authoring worker briefs, rolling up aggregates at wave boundaries, never forwarding raw reports. Cap in-flight children near ten as a rolling window, never blocking batches (which pay the slowest child every round).
- **Workers and verifiers.** One writer per worktree or branch (rule 15). Verification scales to the unit: cheap single-command checks run inline with spot-checked receipts; expensive, judgment-laden, or high-blast-radius units get a dedicated verifier on a different model family. Prefer fewer, broader workers.

## The brief

GOAL (one sentence, executable by a stranger with no chat access), SCOPE (writable paths, forbidden paths, exclusive worktree or branch), CONTEXT (file pointers plus upstream reports pasted in full when depended on), ACCEPTANCE (checkable criteria), VERIFY (exact commands plus gotchas), TIMEBOX (cap; on expiry return partials and stop), FORBIDDEN (no retargets, merges, rebases, force-pushes, out-of-scope fixes, plus unit bans), REPORT (status, branch, head SHA, PRs, verdict, commands run, deviations, follow-ups), STANDING (standing orders pasted verbatim). A field you cannot fill is a unit not scoped yet: refuse to spawn. Size to the unit; a one-command unit collapses to a paragraph still naming goal, scope, verify, and report shape.

## Steps

1. **Frame.** State the done predicate as something countable. Quantify units, effort, stacks, wall-clock budget. Work one agent could finish inside budget is a single run, not this. Name tracks per project; contested decompositions go through `arena` first. Present the framing once; reversible prep proceeds.
2. **Pilot.** Push one unit through the whole path (brief, worker, verification, stack entry, verdict row, merge) to falsify the brief template, the verify recipe, and the unit size while it costs one agent. Fix the contract from pilot evidence before fan-out. Cheap near-identical units pilot as a normal first unit, then fan out on landing.
3. **Scale.** Rolling window refill as children finish; recompute ready work after each drain; relay upstream reports into downstream briefs. Audit one sampled worker brief per track per wave alongside (never gating in front); a failing brief stops that track's next refill and fixes the track instructions, never just the worker. Never resume-chain a brief: respawn fresh with consolidated scope.
4. **Drain.** At batch points (critical section end, track rollup, scheduled wake, before human reports): classify every completion (landed, needs-verify, failed, zombie, noise), record verdicts, spawn the next wave in one message. Never deep-review inline: a completion needing review becomes a verifier unit. Account for every spawned child at rollup; silently redoing missing work hides spend and coverage gaps.
5. **Land continuously.** Integration starts with the first verified unit, alongside remaining waves. Exactly one stacker per stack mutates topology (rebases, retargets, merges); workers never rebase or merge. Babysit one stack each per `babysit.md`, reporting conflicts to the stacker. Advance only on merge or reported head SHAs; a new head SHA voids prior verdicts. PR closes and retargets go through the stacker: closing a base orphans the chain above it.
6. **Verify to the ledger.** Ready-check verdicts keyed by PR plus head SHA are the ledger (a new SHA re-verifies). CI green is an input, not a verdict. Behavioral work needs better than type-check-only. Failed verification gets a fix unit, never a bare re-verify. Externalize on landing (pushed branch, recorded verdict, receipts in the trail): work existing only on one dead machine was never done.
7. **Close.** Drain the final inbox, reconcile every spawned agent to a terminal row, confirm the predicate on the real artifact, confirm every landed PR holds a verdict for its current head, audit the trail per show-me-your-work with its cross-model review, encode recurring corrections into standing orders. Escalation reaches the human batched (irreversible actions, genuine product calls, contradicted standing orders, dead ends surviving replans); everything else acts and logs. Mid-run discoveries fix only frontier-blockers; the rest parks in follow-ups.

**Reply:** at checkpoints and close: predicate plus count, tracks and landings, frontier (PR list plus SHAs), verdict summary, abandons with reasons, gates awaiting the human (the only asks), trail path. Numbers from the records, not narrative, with PR links.
