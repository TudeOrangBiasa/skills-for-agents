# Playbook: ready-check

The half after babysit. Verify each open agent PR independently, classify its risk, and land what your risk authority allows: merge the quick batch (low-risk PASS) and any qualifying medium PR yourself in merge order, then hand the human the rest. Never arm auto-merge: only a read-back MERGED counts as landed.

1. Freeze the list. The PRs the user named, else every open agent PR in the repo. For stacks, record bottom-to-top order and each PR's base.
2. Verify each PR independently with a fresh subagent that did not write it (section 6 brief, `review` role in `docs/agents/models.md`). It runs the PR's head against its base on the real surface (tests, the page, the endpoint) and returns PASS, PASS+NOTES, or FAIL with evidence. Record the head SHA with the verdict and post the verdict as a PR comment. CI green and bot approvals are inputs, not verdicts.
3. Check each verdict still covers the code: the verdict seals the patch, not the SHA. Compare `git patch-id` at the verdict SHA with the current head. The same patch-id means the lane results still stand; a diff limited to tests, docs, or lint config counts the same only with the noise reason written down. Anything else means verify again from step 2.
4. Classify risk per `RISK.md`. Apply the label and write or update the `## Risk` paragraph in the PR body. A FAIL or INCONCLUSIVE verdict is `risk:high` by rule 9. Docs-only proof PRs fail when any linked artifact does not resolve, or the body lists paths instead of rendering proof.
5. Check mergeability per PR: conflicts, required checks, unresolved threads, base branch. A blocker that babysit can clear goes back to `playbooks/babysit.md`; anything else is listed for the human.
6. Order the plan. Stacked PRs merge bottom-up and only as a contiguous verified run from the root: a PASS above a FAIL waits. Each PR lands on its own with `gh pr merge <pr> --squash`, one at a time from the root down the stack. Independent PRs order by risk.
7. Report, high-risk first:
   - **Review first**: each high-risk PR with its link, verdict, the matched rules, and the one thing to check.
   - **Quick batch**: low-risk PRs that passed, in merge order, one line each.
   - **Merge**: merge the quick batch plus qualifying medium PRs one at a time, bottom-up, only contiguous verified runs (`gh pr merge <pr> --squash` each); record each merge SHA. A medium PR qualifies only with a PASS verdict at the current head, green required checks, and no unresolved threads. After each merge, read back `gh pr view <pr> --json state,mergedAt,baseRefName` and report merged only when state is MERGED and base is the trunk: a merge command can claim success while only queueing, and a requested auto-merge may never fire. After a parent merges, retarget each child to the trunk (`gh pr edit <pr> --base <trunk>`), transplant its patch onto the merged result, and push with `--force-with-lease=<branch>:<last-pushed-sha>`. Never touch the stack while landing for any other reason; when a merge stalls, find out why before doing anything else. Stop at the ceiling: a PR above the highest verified contiguous run waits for a fresh pass from step 1. Never arm auto-merge: an armed merge lands code nobody re-verified after the verdict. Run on ask, or scheduled (hourly cron/loop per `/setup-meta` Section G, `docs/agents/unattended.md`) so qualifying batches land without a human in the loop.
   - **Blocked**: FAIL, stale, or conflicted PRs and what each needs.

**Reply:** the four lists above, what you merged and at which SHAs, the stack order, each verdict with who produced it and at which SHA, and a short "Why this way" for any PR whose label might surprise the user.
